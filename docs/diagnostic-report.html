🔍 Root Cause Analysis

The diagnostic tests reveal a DNS resolver misconfiguration in your local Windows environment. However, your network connectivity is completely functional.

What's Happening:

  • Default DNS Resolver: Your system's default DNS service is not responding (returning ECONNREFUSED)
  • External DNS Works: When explicitly using Google (8.8.8.8) or Cloudflare (1.1.1.1) DNS, all domains resolve perfectly
  • Network is Fine: TCP and HTTPS connections work flawlessly to Supabase and all external services
  • Not a Firewall Issue: Port 443 is open and accessible

Possible Causes:

  • DNS Cache Service (Windows) is not running or misconfigured
  • Network adapter pointing to an unreachable DNS server
  • Firewall/Antivirus blocking local DNS resolver
  • WSL2 or Docker DNS issues (if you're using those)

Why It Matters:

For Local Development: Your current setup works fine for testing—use the workaround below
For Production Deployment: Cloud environments may have similar DNS issues. The fixes below will prevent deployment failures.

🛠️ Recommended Solutions

1️⃣ Quick Fix - Code Level (No System Changes)

Use explicit DNS in your Node.js application:

const dns = require('dns').promises; const resolver = new dns.Resolver(); resolver.setServers(['8.8.8.8', '1.1.1.1']); // Use resolver for all DNS queries

✓ No system changes needed | ✓ Works in all environments | ✓ Can be environment-specific

2️⃣ System-Level Fix - Windows DNS

Fix DNS through Windows Settings (Permanent):

netsh interface ipv4 set dnsservers name="Wi-Fi" static 8.8.8.8 primary netsh interface ipv4 add dnsservers name="Wi-Fi" 1.1.1.1 index=2 ipconfig /flushdns

✓ Fixes all applications | ⚠️ Requires admin privileges

3️⃣ Docker/Container Deployment

Add DNS configuration to your Dockerfile:

FROM node:20 RUN echo "nameserver 8.8.8.8" > /etc/resolv.conf RUN echo "nameserver 1.1.1.1" >> /etc/resolv.conf # ... rest of Dockerfile

4️⃣ Kubernetes Deployment

Configure DNS in your pod spec:

apiVersion: v1 kind: Pod metadata: name: lekhiq-app spec: dnsPolicy: "None" dnsConfig: nameservers: - 8.8.8.8 - 1.1.1.1

5️⃣ Verify the Fix

Run the diagnostic test again:

node scripts/test-supabase.js

All tests in TEST 1 should show ✓ after fix is applied
