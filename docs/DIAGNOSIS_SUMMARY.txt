ROOT CAUSE ANALYSIS
-------------------

WHAT'S HAPPENING:
  Your Windows system's default DNS resolver (likely the Windows DNS cache
  service or system resolver) is not responding to queries. However, when
  explicitly using external DNS servers, resolution works perfectly.

POSSIBLE CAUSES:
  1. Windows DNS Cache Service (dnscache) not running/misconfigured
  2. Network adapter pointing to unreachable DNS server
  3. Local firewall/antivirus blocking DNS resolver
  4. WSL2 or Docker DNS service issues
  5. Network adapter configuration error

IMPACT ASSESSMENT:
  ✓ LOCAL DEVELOPMENT: No issue - you can use explicit DNS configuration
  ✗ CLOUD DEPLOYMENT: May fail if cloud environment has similar DNS issues
  ⚠ PRODUCTION: Requires explicit DNS configuration to ensure reliability

================================================================================

RECOMMENDED SOLUTIONS (In order of preference)
----------------------------------------------

SOLUTION 1: Code-Level DNS Configuration (EASIEST)
  No system changes needed. Add to your Node.js application:

    const dns = require('dns').promises;
    const resolver = new dns.Resolver();
    resolver.setServers(['8.8.8.8', '1.1.1.1']);
    // Use resolver for all DNS queries

  ADVANTAGES:
    ✓ No system changes required
    ✓ Works in all environments
    ✓ Can be environment-specific (dev vs production)
    ✓ Can add fallback logic

  RECOMMENDED FOR: Local development, testing, and most deployments

================================================================================

SOLUTION 2: System-Level DNS Fix (Windows)
  Fix DNS through Windows Network Settings (permanent change):

    netsh interface ipv4 set dnsservers name="Wi-Fi" static 8.8.8.8 primary
    netsh interface ipv4 add dnsservers name="Wi-Fi" 1.1.1.1 index=2
    ipconfig /flushdns

  ADVANTAGES:
    ✓ Fixes ALL applications on this system
    ✓ One-time configuration

  DISADVANTAGES:
    ✗ Requires administrator privileges
    ✗ Global change affects all applications

================================================================================

SOLUTION 3: Docker Container Deployment
  If deploying via Docker, add DNS configuration to Dockerfile:

    FROM node:20
    RUN echo "nameserver 8.8.8.8" > /etc/resolv.conf
    RUN echo "nameserver 1.1.1.1" >> /etc/resolv.conf
    # ... rest of Dockerfile

  Or at runtime:

    docker run --dns 8.8.8.8 --dns 1.1.1.1 your-app:latest

================================================================================

SOLUTION 4: Kubernetes Deployment
  Configure DNS in Kubernetes pod spec:

    apiVersion: v1
    kind: Pod
    metadata:
      name: lekhiq-app
    spec:
      dnsPolicy: "None"
      dnsConfig:
        nameservers:
          - 8.8.8.8
          - 1.1.1.1

  Or use it in your Deployment/StatefulSet spec's podSpec section.
